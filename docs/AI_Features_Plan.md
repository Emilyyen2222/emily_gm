## 決策總覽

| 項目 | 決定 |
|---|---|
| 做的順序 | ① AI 問答 → ② 新聞（含雙語） → ③ 早安推播每日一句 → ④ 健身紀錄 A |

## 隱私原則（所有功能共用）

- **群組**：AI 絕不讀取、也不提及任何人的紀錄。群組裡只有一般問答與新聞。
- **一對一**：AI 只能讀**本人**的紀錄，而且只讀數字、選項與自我照顧的項目名稱，**不讀日記、各種備註與花費**。
- 送給 AI 的資料以「最少」為原則：不送 LINE 暱稱、不送 userId。
- 會送出使用者資料的功能，需要本人先按下同意。

## ① AI 問答

### 觸發
- 一對一：任何訊息都會回應；群組：只在被 @ 時回應（沿用現有規則）。
- 現有指令「記錄／今天／本週／說明」照舊，**其他看不懂的訊息改交給 AI**，不再回說明卡片。

### 行為
- 每題獨立，不記得前面的對話。
- 每人每天最多 **30 題**（以台北日期計）。超過時回覆一句說明，不呼叫 API。
- API 額度用完或出錯時，回覆「AI 暫時不能用」的說明，不會沒有反應。
- 一對一聊天時先顯示 LINE 的「輸入中」動畫（Loading Animation API，只支援一對一），讓使用者知道 bot 有在處理。

### 同意流程（只在一對一）
1. 第一次問 AI 時，先存下這個問題，回一張說明卡片，附兩顆按鈕：**「同意」／「不用，只回答一般問題」**。
2. 按下任一顆後（postback 事件），記下選擇，**直接回答剛剛存下的那題**。
3. 選「不用」的人照樣可以用一般問答，只是 AI 不讀紀錄。
4. 打「AI 設定」可以重新選擇。
5. 卡片文字與各種固定回覆已確認，見 `server/utils/botReply.ts` 的 `aiConsentCard`、`AI_TEXT`。

### AI 可以讀的資料（一對一且已同意）
最近 14 天本人的：睡眠分數與時數、就寢／起床時間、體溫、心情選項、排便有無與時間、出門／下班時間、過敏選項、自我照顧的**項目名稱與達成情況**（包含自訂項目）。

**不讀**：睡眠備註、心情備註、私人備註、舊的排便／過敏備註、**花費**（有分享／不分享之分，一律不讀）、LINE 暱稱。

### 資料表（新增）
見 `supabase/migrations/016_ai.sql`：
- `users` 加欄位：`ai_consent`（`granted` / `declined` / null＝還沒問過）、`ai_consent_at`、`ai_pending_question`。跟 `habits`、`expense_label` 一樣屬於「這個人的設定」，不另開表。
- `ai_usage`：`user_id`、`usage_date`、`count`，搭配 function `ai_usage_take` 在資料庫裡一步完成「沒超過上限就 +1」。

照現有做法啟用 RLS、不建 policy，只有 server routes 進得來。

## ② 新聞（「@bot 新聞」「@bot AI新聞」）

### 來源
**健康新聞**：Heho 健康；ScienceDaily 睡眠、營養、運動、壓力；MIT Technology Review 生技與健康。

**AI 新聞**：Hacker News（Algolia API）；Reddit r/ClaudeAI、r/LocalLLaMA、r/artificial；TechCrunch AI、The Verge AI、iThome；Anthropic 官網 /news、Claude blog（解析網頁，沒有 RSS）。

所有來源都免費，實測過都抓得到。要注意：
- Reddit 常常擋雲端主機的 IP，部署到 Vercel 後要再測一次；抓不到就先拿掉。
- Anthropic 官網和 Claude blog 是解析網頁，官網改版就可能失效。單一來源失敗不能影響其他來源。

### 產生方式
**另開一個排程，每天台北 08:00 產生**（Vercel 免費方案可以有多個排程，但每個一天一次，而且會在該小時內任意時間執行，所以最晚 08:59 完成）。
抓各來源最近 24～48 小時的標題與簡介，交給 Haiku 挑 3 則寫成摘要，存起來給當天所有人用。有人問時直接讀出來回覆，不當場呼叫 AI。
08:00 以前問，拿到的是前一天的新聞。當天產生失敗時也會回前一天的，並註明日期。
11:00 的早安提醒排程維持不變。

### 格式
每則：標題＋兩三句摘要＋連結，**完整中英對照**（中文摘要一次、英文摘要一次），附重點單字。AI 新聞可以保留技術用語（讀者都是工程師）。
先做完整對照版試用，實際在 LINE 上太長再改成「中文摘要＋一句英文」。

做成**卡片**，3 則左右滑動，沿用現有卡片風格。

### 資料表（新增）
- `news_digests`：`kind`（`health` / `ai`）、`digest_date`、`content`（產生好的訊息 JSON）、`created_at`

## ③ 早安推播每日一句

- 附在 11:00 早安提醒的**同一次 push** 裡，**另外一張小卡**跟在提醒卡片後面（多一個對話框，不多用額度）。
- 在 08:00 的新聞排程裡一起產生好；產生失敗時，早安提醒照常發送，只是不附這一句。
- 內容：一句跟睡眠、心情、運動、健康有關的英文，加上中文意思和重點單字。不含任何個人資料。
- ⏳ 待確認：內容來源與格式（先給範例）。

## ④ 健身紀錄 A

記錄每次訓練的動作、組數、重量，在歷史頁看進步曲線。細節另外討論。

| 項目 | 估算 |

| AI 問答 | 實測每題約 500 in / 50～100 out token ≈ US$0.001（附紀錄時會多一些）；5 人 × 每天 3 題 ≈ US$0.5／月 |
